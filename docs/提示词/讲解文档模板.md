# 讲解文档模板

写飞书讲解文档的规范。两条铁律先立在这里，后面所有规则都是为了服务这两条：

1. **简洁明了**：文档里只放必要内容。一段简短引入后直入主题，不铺垫、不复述、不解释自己。
2. **通俗易懂**：这是一份**讲解**，不是说明书。用口语把话说明白，带点对话感，但**不滥用比喻**。

---

## 一、章节骨架

| 层级 | 内容 | 职责 |
|---|---|---|
| h3 | 章（第零章 / 第一章 / 第二章） | 下面只放一个引用块，交代对应哪个 Assignment |
| h4 | 大节（1 架构 / 2 训练 / 3 实验 / 补充 1） | 同样先放一个引用块，交代对应 PDF 的哪几章 |
| h5 | 节（1.1 / 2.3 / 3.4） | 教学的基本单位，一节讲一件事 |
| h6 | 知识点（1.3.1 线性层 / 3.4.2 训练优化） | 只在内容多的节出现；一个 h6 对应一个 Problem 或一个子话题 |

编号规则：

- h5 写「大节号.序号」，h6 写「节号.序号」，与 PDF 的章节号**不要求一致**（我们按讲解顺序重新编号）
- 补充篇另起编号，Problem 改称「**问题 N**」并从 1 重数
- 标题不加句号，不带"（上）""（续）"这类尾巴

## 二、四套模块模板

内容再多，落到文档里也只走这四条链。

### A. 知识点（有代码题）

一个 h6 循环一次，链固定：

```
定位句        1 句，说"这是什么、干什么用"
定义式        居中的公式段，行尾 \tag{n}
             紧接同一段"其中，…"逐符号解释
输入 / 输出    两行，形如 (batch_size, sequence_length, d_in)
结构图        无图注，前后各一句衔接
问题卡        💡 callout：Problem N → 要求 → 参数 → 初始化
脚手架        PRE，只留签名 + pass
引用块        解释脚手架的用意，或一句关键取舍
```

示例（1.3.1 线性层）：`P P P P IMG CALL PRE QBOX` 八个块讲完，约 800 字符。

### B. 推导题（第二章主力，第一章没有）

```
命题          1 句，回答"为什么值得算这个"
设定与记号    沿用统一符号，一条 li 一个符号
推导          每步一段居中公式，步间一句"由…可得"衔接
结论          加粗一行给出结果式，再用一句说它意味着什么
问题卡        Problem N：要求给出推导 + 结论 + 一句解释
```

推导题的正文就是答案的一半，**不能只写"详见 PDF"**。链大约 `P P(公式) P P(公式) P QBOX CALL`。

### C. 实验（跑起来才算完）

```
承接句        1~2 句，把上一节的结果接过来
h6 切子任务   基准 / 消融 / 调参，各占一个 h6
引用块        数据集示例（原文摘录）、外部资源
问题卡        要求 = 操作清单（4~6 条）→ 实现要点（2 条）
引用块        个人实测结果，或踩坑提醒
```

实验节**不放代码块**，只给命令与配置。第一章 3.2 / 3.4 都是这个形状。

### D. 短节（前置知识、补充篇）

三块就够：`P`（是什么）+ `QBOX`（为什么这么讲 / 术语）+ `PRE`（提纲或脚手架）。
第零章 0.1~0.3 都是这种，一节 300~600 字符。

## 三、问题卡

两种写法，别混。

**代码题**

```
Problem 12: 学习率超参调优 (1 分)
要求：      动作 + 可检查的产出（分数 / 图 / 表 / 结论）
              · 参数用 UL，一条一个，格式「名字: 类型 — 中文含义」
              · 初始化方式、数值范围写在这里
实现要点：   2 条以内，给方向不给答案
```

**推导题**

```
Problem 3: 基线的作用：方差计算 (2 分)
要求：      给出完整的推导过程，并写出最终结论式
              · 明确"用什么符号表示什么"，与正文一致
              · 说明结论在什么条件下成立
```

字段名一律 `<b>` 加粗并带冒号：**要求：**、**实现要点**、**注意：**、**设计要点：**。
正文句子不加粗。

## 四、块级规范

| 元素 | 用什么 | 约束 |
|---|---|---|
| 公式 | 段落内的 equation | **不用独立公式块**；独立成式时该段居中，行尾 `\tag{n}` 顺序编号 |
| 符号说明 | 紧跟公式的同一段 | 以"其中，"起头，公式用行内 equation |
| 列举 | UL（并列 / 参数）、OL（步骤 / 顺序） | 一条一个信息点，单条不超过两行 |
| 问题卡 | callout，emoji 💡，橙底 | 一节最多 3 个；卡内只放 p / ul / ol |
| 代码 | PRE，纯文本（不高亮） | 脚手架只留签名 + 中文参数说明 + pass；完整实现进 `scripts/` |
| 补充说明 | QBOX（引用块） | 五种用途：节导语、术语解释、数据示例、取舍说明、个人经验 |
| 图 | IMG | 无图注；正文要有一句"如下图所示"接住 |
| 表 | TABLE | 放参数对比、资源估算；**不能放进 callout** |
| 加粗 | 只加字段名 | 一节最多 3 处，正文不加粗 |
| 链接 | 论文 / 官方仓库 / 数据集 | 放术语首次出现处，不放文末堆列表 |
| 篇幅 | — | 单节 1.3~1.7 千字符；单知识点 700~900 字符；超了就拆 h6 |

## 五、表述风格

**这么写**

- 人称用"我们"，面向读者用"你 / 大家"，不用"本文"
- 单句 20~40 字，一段 1~3 句，先给结论再解释
- 术语中英并列，首次出现给全称：均方根归一化（RMSNorm）
- 讲机制时允许一个比喻，讲完立刻回到术语，别顺着比喻往下编
- 承认不确定：自己跑过的数字照实写，没跑过的写"预计"或不写
- PDF 里"显然、易得、不难发现"带过的地方，这里必须补一段

**别这么写**

- 不复述 PDF 原文，也不写"本节将介绍 A、B、C"这种目录句
- 不堆形容词（"非常重要的核心关键"），不写"大家一定要记住"
- 不连续三段纯文字：一段话后要么列表、要么图、要么卡片
- 不贴没验证的数字，不写"据说""大概能到"
- 不用网络热词和语气词（"yyds""懂了吧""哈"）

## 七、发布前自检

1. 每个 h5 标题下，第一段是否在说"这是什么"，而不是"我们将学习"
2. 每个 Problem 是否都有明确的产出要求（分数、图、表、结论）
3. 公式是否都编了号，符号是否都在正文解释过
4. 有没有连续三段以上的纯文字
5. 一节的字符数是否落在 1.3~1.7 千之间
6. 加粗是否只出现在字段名上
7. 引用块是否承担了具体职责（不是随手一句感慨）
8. 读一遍：像不像在跟人说话，有没有一句是"可以不写"的
